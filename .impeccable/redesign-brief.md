# บรีฟรื้อ UI ทั้งโปรเจกต์ — ยืนยันแล้ว

- ที่มา: /impeccable shape · 26 ต.ค. 2569 · โหมด Operate
- ฐานความจริงผลิตภัณฑ์: PRODUCT.md
- คะแนน critique: 28/40 (Good)

## 1. โจทย์
- รื้อ UI ทั้งแอปชุดใหม่ในครั้งเดียว (big-bang)
- ไม่เพิ่มฟีเจอร์ใหม่
- แก้ 2 ปัญหา: ความหนาแน่นของหน้าจอ (UI density) และเลย์เอาต์ที่พัง
- เป้าหมายใช้งาน: จบงานเองได้ ไม่ต้องขอความช่วยเหลือ ไม่กลัวกดผิด

## 2. ผู้ใช้และอุปกรณ์
- หมอนวด/พนักงาน 1–3 คน ใช้มือถือส่วนตัวทั้งวัน
- เจ้าของร้าน: ดูตัวเลข ตรวจบิล ตารางจอง ตั้งค่าร้าน
- แท็บเล็ตที่เคาเตอร์ ใช้ตอนรับเงิน
- ทุกหน้าต้องใช้ได้ดีตั้งแต่จอ 390px จนถึงแท็บเล็ต

## 3. เกณฑ์วัดความสำเร็จ
- ตัวอักษรจุดใช้งานหลัก ≥ 11.5px (เดิมมี 32 จุดที่ ≤ 10.5px)
- Contrast ≥ 4.5:1 ทุกข้อความ (เดิมแย่สุด 2.8:1 ที่หัวข้อหน้าบิล)
- ปุ่มกดในงานประจำวัน ≥ 44px (เดิมไอคอนแก้ไข/ลบเล็กแค่ 24–26px)
- สถานะ "รอ / สำเร็จ / ผิดพลาด" ใช้ชุดเดียวทั้งแอป (เดิมมี 4 ชุดปนกัน)
- เมนูล่างของเจ้าของ 7 ทาง → เหลือไม่เกิน 5

## 4. แนวทางรื้อ 5 ข้อ
1. ระบบขนาดตัวอักษร (type ladder) ใหม่ — จำนวนขั้นน้อย อ่านชัดก่อน คุมความหนาแน่นด้วยลำดับชั้น ไม่ใช่พิมพ์เล็กลง
2. แต่ละหน้าแบ่งกลุ่มเนื้อหาไม่เกิน 3 กลุ่มต่อจอ
3. รวมชุดสถานะเป็นชุดเดียวทั้งแอป
4. เมนูล่างเจ้าของเหลือไม่เกิน 5 ทาง
5. การกันพลาดเดิมที่ดีคงไว้ครบ: รหัสเจ้าของ, ยืนยัน 2 ขั้นตอนสำหรับเงินโอน, ต้องเลือกหมอก่อนเช็คบิล

## 5. ลำดับงาน
1. ระบบฐาน: type ladder + ระยะห่าง (spacing) + ชุดสถานะ + ขนาดปุ่ม ≥44px + contrast
2. หน้าล็อกอิน + POS
3. หน้าบิล + ภาพรวม
4. จองออนไลน์ + จัดการร้าน + รายจ่าย + ค่าแรง
5. ปิดท้าย: polish + ตรวจ a11y + จอมือถือ/แท็บเล็ตทุกหน้า

## 6. แตะได้ / ห้ามแตะ
แตะได้:
- index.css และ CSS ที่เกี่ยวข้องทั้งหมด
- โครงเมนู / การเรียงลำดับ / การจัดกลุ่ม ของทุกหน้า
- ขนาดตัวอักษร น้ำหนัก สีของข้อความ (ภายในโลกสีครีมเดิม)

ห้ามแตะ:
- ทุกอย่าง logic ธุรกิจ: cloudSync.js, data object + business logic ใน App.jsx, lib/billing.js
- Supabase schema + Edge functions
- ระบบบทบาท / PIN
- Brand: สีครีม–เบจ, ฟอนต์ Kanit/Sarabun, logo.jpg, ศัพท์ร้านจริง (เช็คบิล ตั้งหมอ ประกันมือ)
- Anti-goals: ไม่เพิ่มฟีเจอร์ ไม่เปลี่ยนโลกสี ไม่ทำแดชบอร์ดแบบ SaaS

## 7. ข้อมูลและสถานะที่ต้องออกแบบ
- หมอ 1–3 คน ห้อง 1–2 ห้อง
- บิลตัวอย่าง: 4 บริการขึ้นไป, ชื่อไทยยาว, สรุปยอดตอนจ่ายชัดเจน
- คิวบิลทั้งจอ: ตอนเช้าร้านเปิดเจอหลายบิลพร้อมกัน
- สถานะต้องมีครบ: กำลังโหลด, กำลังรีเฟรช, ว่าง, ผิดพลาด, อัปเดตพร้อม (update banner)
- มือถือถูกทำรายการกลางคัน: ออกจากแอปแล้วกลับมา งานยังคงอยู่
