# ออกแบบ: เพิ่มตัวเลือก ลูกค้าหน้าร้าน / ลูกค้าจอง ในหน้า POS

วันที่: 2026-10-26 · ผู้ตัดสิน: เจ้าของร้าน (โดยคุยผ่านผู้ช่วย) · สถานะ: รอยืนยัน

## ที่มาและเป้าหมาย

หน้า POS วันนี้เปิดบิลได้เฉพาะ "ลูกค้าหน้าร้าน": รายการ → ระยะเวลา → หมอนวด → เวลา → ตรวจสอบ
ต้องการเพิ่มทางเลือก **ลูกค้าจอง** = ลูกค้าโทรมาจองกับพนักงาน พนักงานเปิด "บิลจอง" ไว้ให้ล่วงหน้า
(จองวันไหนก็ได้) โดยบันทึก **ชื่อลูกค้า** + **คนที่รับจอง** และยังไม่ต้องรู้ว่าหมอคนใดจะเป็นผู้ให้บริการ

**เป้าหมาย**
1. POS มีหน้าเลือกประเภทลูกค้า 2 ปุ่ม: ลูกค้าหน้าร้าน / ลูกค้าจอง
2. Flow ลูกค้าหน้าร้าน = เดิมทุกอย่าง (1 รายการ 2 ระยะเวลา 3 หมอนวด 4 เวลา 5 ตรวจสอบ)
3. Flow ลูกค้าจอง = 1 ชื่อลูกค้า(+คนรับจอง) 2 รายการ 3 ระยะเวลา 4 เวลา(เลือกวันที่ได้) 5 ตรวจสอบ — **ไม่มีขั้นหมอ**
4. "คนรับจอง" แตะเลือกจากหมอที่เช็กชื่อวันนี้ **หรือ** พิมพ์ชื่ออิสระ (เผื่อเจ้าของร้านเปิดบิลจองเอง)
5. บิลจองมีหมอเว้นว่างได้ — เมื่อลูกค้าถึงร้าน ค่อย "ตั้งหมอ" ที่การ์ดบิลที่เปิดอยู่ ก่อนเช็คบิล
6. บิลจองไม่รบกวนยอดขาย/คอมมิชชัน/ปิดวันของวันอื่น

**ไม่ใช่เป้าหมาย (non-goals)**: หน้าใหม่, การเชื่อมระบบเว็บจอง (BookingBillsSection ทำงานเดิม),
การจองหลายหมอ/หลายห้องต่อบิล, ระบบแจ้งเตือน no-show, การแตะ auth/RLS
**สิ่งที่ทำให้งานล้มเหลว**: บิลจองไหลไปโชว์/vấnยอดของวันที่เปิดบิลแทนวันที่ให้บริการ

## ข้อจำกัด (constraints)

- โมเดลบิลเดิม: หมอระดับบิลคนเดียว + เวลาเริ่ม–จบต่อกันอัตโนมัติ — คงไว้ทั้งหมด
- ไม่มีทะเบียน "พนักงานหน้าร้าน"; แหล่งเดียวที่ใกล้ที่สุดคือเช็กชื่อ (`data.attendance[dateStr][therapistId]`)
- Migration Supabase รัน manual ใน SQL Editor (`supabase/migration_*.sql`, ไม่มีตัวรันอัตโนมัติ)
- ทุกวันที่/เวลาต้องผ่าน `src/utils/bkk.js` (วันธุรกิจตัดที่ 03:00)
- พนักงานเรียก edge function `booking-admin` ไม่ได้ (ไม่มีรหัสเจ้าของ) — flow นี้จึงไม่พึ่ง API ของเว็บจองเลย

## ทางเลือกที่พิจารณา (approaches)

- **A — บิลจอง = บิล open ที่มีวันที่รับบริการของตัวเอง (ที่เลือกใช้)**: บิลธรรมดา + ฟิลด์ใหม่
  (ประเภทลูกค้า / วันที่ให้บริการ / คนรับจอง) หมอเว้นว่างได้ ไหลต่อในระบบบิล–คอมมิชชัน–ปิดวันเดิมทั้งหมด
  งานพอดีตัว ต้องรัน migration 1 ครั้ง
- **B — คิวจองเป็นเอนทิตีแยก** ลูกค้ามาแล้ว "แปลงคิว → เปิดบิล": โมเดลถูกหลักแต่ต้องเพิ่มตาราง + sync
  + หน้าแปลง งานใหญ่ 2–3 เท่า — ตัด
- **C — ให้พนักงานใช้ระบบเว็บจองแทน**: ไม่ผ่าน เพราะเรียก booking-admin ด้วยสิทธิพนักงานไม่ได้ — ตัด

## สิ่งที่ตกลงร่วมกันแล้ว (decided)

1. **หน้าเลือกประเภทลูกค้า** เป็นขั้นแรกของ POS (ปุ่มใหญ่ 2 อัน) ค่าเริ่มต้น = ลูกค้าหน้าร้าน ย้อนกลับมาเปลี่ยนได้
   (เปลี่ยนประเภทกลางทาง = เริ่ม flow ใหม่ตั้งแต่ขั้น 1 ของประเภทนั้น กรองสิ่งที่เลือกไว้ทิ้งพร้อมยืนยัน)
2. **Flow จอง ขั้น 1**: ช่อง "ชื่อลูกค้า" (ต้องกรอก) + "รับจองโดย" (แตะหมอที่เช็กชื่อวันนี้ จาก
   `attendance[bizToday()]` อ้างอิง `data.therapists` active — หรือพิมพ์ชื่ออิสระ; ต้องมีที่ใดที่หนึ่ง)
   ถ้าวันนี้ยังไม่มีใครเช็กชื่อ ปุ่มลิสต์ช่องว่างพร้อมข้อความชวนให้พิมพ์ชื่อแทน
3. **ขั้น เวลา ของ flow จอง**: เพิ่มแถวชิปเลือก "วันที่รับบริการ" — วันนี้ (มากกว่า) + วันถัดไปสูงสุด
   **7 วัน** (ตัวเลขนี้ให้ช่างปรับได้); เวลาเริ่มใช้ TimeSlotPicker เดิม (12:00–22:30, ขั้น 15 นาที)
4. **กันชนเวลา ของบิลจอง** (หมอยังไม่รู้): ช่องว่างคิดรวมบิลหน้าร้าน open + บิลจอง open ของ
   "วันที่รับบริการ" เดียวกันทุกหมอ (กันห้อง/กรณีเลือกหมอไม่ได้ตั้งแต่ต้น) เมื่อ "ตั้งหมอ" ภายหลัง
   ถ้าเวลาชนหมอคนนั้น → แจ้งเตือนให้แก้เวลาที่แก้ไขบิล (ยังตั้งได้แต่เตือนก่อน)
5. **โมเดลฟิลด์ใหม่บนบิล** (รวมทั้งบิล open/paid): `customerType: 'walkin'|'booking'`,
   `bookedDate: 'YYYY-MM-DD'` (วันธุรกิจ "วันให้บริการ"), `bookerName: string`, `bookerId: string`
   (รหัสหมอถ้าเลือกจากลิสต์, ว่างถ้าพิมพ์เอง) บิลจองไม่ใส่หมอวิ่ง/ค่าน้ำมัน; โปร/ส่วนลดใช้เหมือนเดิม
   บิลเก่าทั้งหมดถือเป็น `walkin` (`bookedDate` ว่าง → ใช้วันธุรกิจจาก `b.date` ตามเดิม)
6. **วันที่ธุรกิจที่ใช้จัดกลุ่มบิล**: บิลจองใช้ `bookedDate` เสมอ (open, paid, cancel ทุกสถานะ) —
   บิลอื่นใช้กติกาเดิม (`bizDateOf(paidAt||date)`) ลงมาที่ OpenBillsSection/PageBills/ตัวนับวัน (dayCounts)
   ให้ทุกจุดใช้ฟังก์ชันคำนวณวันธุรกิจที่มีผลตัวเดียวกัน กันมุมมองแตกกัน
7. **การ์ดบิลที่เปิดอยู่** (`OpenBillsSection` ใน PageBills): บิลจองไปแสดงกลุ่ม **ลูกค้าจอง** คู่กับ
   เดอร์จองเว็บ กรองด้วยชิปเลือกวันที่ที่มีอยู่แล้ว บิลจองที่หมอยังว่างแสดงป้าย "รอตั้งหมอ" + แถวแสดง
   ลูกค้า / วันที่ / เวลา / รายการ / คนรับจอง และตัวนับ "ลูกค้าจอง N" รวมบิล manual ด้วย
8. **ปุ่ม "ตั้งหมอ"**: dialog ใช้ชุดตัวเลือกแบบขั้นหมอหน้าร้าน (หมอประจำทั้งหมด active + หมอวิ่ง
   พิมพ์ชื่อได้) กดแล้วเซ็ต `therapistId/therapistName` ทั้งระดับบิลและทุก item บันทึก audit
   "ตั้งหมอบิลจอง" — ห้องบิล/paid ปกติ
9. **เช็คบิล (paid)**: บิลจองที่หมอยังว่าง → บล็อกพร้อมข้อความ "ตั้งหมอก่อนเช็คบิล" (กันคอมมิชชันหาหมอไม่เจอ)
10. **แก้ไขบิลที่เปิดอยู่**: ใช้ของเดิม + แสดง/แก้ "คนรับจอง" ได้ (และลูกค้า/เวลา/รายการเหมือนเดิม)
11. **หน้า POS**: เพิ่มการ์ดเล็ก "คิวที่จองล่วงหน้า" (วันนี้ + ถัด ≤7 วัน: วันที่ · เวลา · ลูกค้า ·
    รายการ · คนรับจอง · ป้ายรอตั้งหมอ) — ทางเลือกของผมเพื่อให้พนักงานเห็นคิวโดยไม่ต้องสลับไปหน้าบิล
    (ตัดได้ถ้าเห็นว่าเกิน)
12. **Supabase**: `supabase/migration_pos_booking_bill.sql` เพิ่ม 4 คอลัมน์ต่อ bills เป็น
    `customer_type`/`booked_date`/`booker_name`/`booker_id` (text, ค่า default ว่าง/`'walkin'`) +
    อัปเดต `cloudSync.js` (`toBillRow`/`fromBillRow` + `BILL_DROP_KEYS`) ใช้กลไก tolerant เดิม
    (DB ยังไม่รัน migration = ฟิลด์ตัดออก + ขึ้น banner เตือน ให้รัน migration)
13. **audit log**: "เปิดบิล (รอเช็คบิล)" → บิลจองใช้ข้อความ "เปิดบิลจอง (รอลูกค้า)" + แสดงลูกค้า/วันที่/คนรับจอง
